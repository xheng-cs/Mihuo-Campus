# 觅活（Mihuo Campus）· 校园活动与机会聚合平台

> 珠海科技学院计算机协会软件部 2026 秋季纳新第二轮考核作品
> 零依赖纯前端 · 打开即用 · 26 条题目模拟信息全量使用

「觅」是发现，「活」是活动与机会。**觅活**面向在校学生、重点照顾新生，
把来源各异、质量参差、状态多变的校园信息，整理成一张
**「看得懂、分得清、信得过、赶得上」** 的校园机会地图。

## 一、产品名称

**觅活（Mihuo Campus）** —— 校园活动与机会聚合平台

## 二、主要解决的问题

1. **信息分散、来源混杂**：比赛、讲座、招募、志愿、学生自发约球/组队散落各处，学生
   （尤其是新生）不知道该看哪、该信谁。觅活将校级（20 条）、学院（2 条）、学生发布（4 条）
   三个来源聚合到一个入口，并用颜色分层标识可信度。
2. **状态难以判断**：报名中 / 即将截止 / 已截止 / 候补可入场 / 长期招募 / 直播已结束待回放 /
   资料提取限时……产品以考核日（2026-09-19）为基准**自动计算每条信息的状态与倒计时**，
   用户不用自己算「还来不来得及」。
3. **补充通知难关联**：09 号是 01 号的补充通知（时间地点变更）、20 号是 03 号的补充说明
   （开发名额已满）。不关联起来，用户会被旧信息误导。觅活自动合并展示并在原信息上打「已更新」角标。
4. **低质信息干扰**：24 号「零门槛日结 + 私加微信」、25 号「标题交流、正文带货」是题目明示的
   低质/推广信息。觅活用**可信度分级 + 规则化风险检测 + 举报机制**平衡开放发布与平台秩序，
   而不是一刀切删除。
5. **学生发布门槛**：学生想约球、组队、找搭子，缺少一个「发出去就有人看」的渠道。
   觅活提供三步发布表单，发布内容**立即进入正常信息流**，可被搜索、筛选、收藏、报名与举报。

## 三、核心功能

| 功能 | 说明 |
| --- | --- |
| 🧭 信息发现 | 26 条信息全量呈现：分类（6 类）/ 来源（3 级）/ 状态筛选、关键词搜索、4 种排序 |
| 📄 活动详情 | 结构化详情：时间、地点、对象、人数、费用、报名条件、状态徽章与实时倒计时 |
| 📝 报名参与 | 报名表单（姓名/年级/学号/联系方式/自我介绍）→ 状态持久化 → 可取消；支持审核制（14 号）、候补（19 号）、长期招募（08/16 号）三种差异流程 |
| ✍️ 学生发布 | 三步发布（基本信息 → 时间地点 → 确认），内容进入信息流，支持编辑、删除 |
| ⭐ 我的空间 | 收藏 / 我的报名 / 我的发布三个列表，**刷新或重开浏览器后数据全部保留**（localStorage） |
| 📅 日程时间轴 | 未来 7 天按天聚合：活动开始、报名截止、作品提交截止、回放上线、资料提取失效 |

## 四、运行方式

**在线体验（推荐，无需任何安装）**：<https://xheng-cs.github.io/Mihuo-Campus/>

**本地运行，零依赖，两种方式任选：**

```bash
# 方式一：直接双击 index.html（Chrome / Edge / Safari 均可）
open index.html

# 方式二：本地静态服务器（推荐，行为最标准）
python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

无构建、无 npm install、无后端。所有用户数据保存在浏览器 localStorage。

**时间基准说明**：产品默认以考核日 `2026-09-19 12:00` 为「今天」计算全部状态。
想验证时间敏感逻辑（如 9/20 后回放上线、9/22 后报名截止），可加 URL 参数模拟：

```
http://localhost:8080/?now=2026-09-22T19:00   # 模拟 9/22 晚查看
```

**测试**：

```bash
node --test                 # 26 项单元测试（逻辑/数据完整性/存储层）
bash tools/browser-smoke.sh # 无头 Chrome 端到端：渲染→搜索→报名→收藏→发布→举报→刷新持久化
npm run start               # 快速起服务（等价于 python3 -m http.server 8080）
```

## 五、自主设计的实用/创新功能

1. **⏰ 截止雷达**：首页顶部聚合「72 小时内截止」的机会卡片，每条带自然语言倒计时
   （「距截止 1 天」「距截止 6 小时」），红点呼吸动画提醒——把「错过截止」这个最高频的
   真实痛点直接消掉。配套「3 天内截止」一键筛选。
2. **🛡️ 可信度体系与内容治理**：来源三级分层（校级 > 学院 > 学生）＋规则化风险检测
   （私加微信 / 日结兼职话术 / 商家购买链接 / 主办方时间地点缺失）→ 风险横幅、
   推荐排序降权、一键举报、学生发布默认「待核验」。24 号信息带红色高风险警示并提示防骗，
   25 号带「疑似商业推广」标记——这是对题目「多来源信息质量问题」的直接产品化回答。
3. **🔗 补充通知自动关联**：01↔09、03↔20 合并展示，原信息卡带「已更新」角标，详情页
   展示合并后的最新口径，并诚实标注「两条通知时间口径不一致，请以最新补充通知为准」。
4. **📅 日程时间轴**：未来 7 天按天聚合「活动开始 + 报名截止 + 作品提交 + 回放上线 +
   资料失效」五类事件，一眼看清今天干什么、明天截止什么。
5. **🌱 新生模式**：顶部一键开关，只显示零基础/新生友好内容（01、02、06、14、18、23 等），
   直接服务「新生体验」这一题目重点。
6. **✍️ 发布风险自检**：发布表单实时检测标题/简介/联系方式中的风险关键词，
   边输入边提示，发布前强制确认——把治理前置到「发布」环节，而不是事后删帖。

## 六、在题目材料或产品设计中主动发现并处理的一项关键问题

**发现的问题**：题目明确给出的 24、25 两条学生发布信息存在真实的质量风险——
24 号自称「零门槛、日结」并要求添加私人微信、未提供主办方与地点，是典型的非正规兼职
特征；25 号标题为技术交流、正文却是商家优惠与购买链接，属于「披着活动外衣的广告」。
若平台对它们一视同仁，新生极易被误导甚至蒙受损失；若直接删除，又违背开放发布的初衷。

**处理方案**（完整落地在产品中）：
1. **分层呈现而非删除**：两条信息保留可见，但带红色「高风险提示」/ 橙色「疑似商业推广」
   横幅，明确写出风险原因与防骗建议（勿轻信日结话术、勿添加陌生微信、勿转账）；
2. **排序降权**：推荐排序中高风险信息自动沉底，正常信息优先展示；
3. **人人可举报**：所有信息都有一键举报（广告推广/疑似诈骗/信息不实/内容不适宜/其他），
   举报后标记「已举报 · 复核中」并持久化；
4. **规则透明可解释**：风险检测是公开的关键词规则（见 `js/logic.js`），不搞黑盒，
   学生发布时同样会被检测，保证规则对官方信息和用户内容一视同仁；
5. **治理前置**：学生发布默认「待核验」标记，发布表单内置反诈发布须知与风险自检。

另外还处理了一处材料细节问题：01 号原通知「9/20 起每周六 19:00」与其补充通知
「首次训练改为 9/21 19:30」在日期/星期口径上互相矛盾（2026-09-20 实为周日）。
产品没有替主办方「纠正」，而是合并展示并在详情页诚实标注「两则通知的时间口径不一致，
请以最新补充通知为准」，把判断权留给用户。

## 七、下一步最希望完善的内容

1. **真实后端与账号体系**：报名数据真实落库、发布走真实审核流、举报有仲裁后台——
   目前为纯前端演示，数据在本地浏览器；
2. **提醒订阅**：报名后自动在截止前 24h/2h 提醒（推送或邮件），这是「截止雷达」的自然延伸；
3. **日历互通**：一键导出 ICS 订阅，把时间轴同步进手机日历；
4. **信息质量评分模型**：把关键词规则升级为多维度加权评分（来源、完整度、历史举报、
   发布者信用），支持管理员复核界面；
5. **报名后社交**：报名同一活动的人可见「同行者」、发布者可查看报名名单，
   服务「找搭子、组队」的深度需求。

## 数据说明

全部 26 条信息来自考核题目「四、校园活动与机会信息」，仅做结构化整理，未增补题目
未提供的事实；题目未注明的信息（费用、地点、报名方式等）一律如实显示「未注明」。
